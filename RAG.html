What is RAG?

Retrieval-Augmented Generation combines LLMs with external knowledge retrieval. Instead of relying solely on training data, RAG systems fetch relevant documents at query time.

RAG = Retrieval + Augmented + Generation
🧠 Foundation
02

Document Ingestion Pipeline

Documents are loaded, split into manageable chunks, converted to vector embeddings, and stored in a vector database with metadata.

docs → split(512) → embed() → vector_db.store()
📄 Ingestion
03

Vector Embeddings

Each chunk becomes a high-dimensional vector. Similar concepts cluster together, enabling semantic search beyond keyword matching.

embed("RAG improves accuracy") → [0.023, -0.156, ...]
🧮 Embeddings
04

Similarity Search

Cosine similarity finds the closest document chunks — those most semantically relevant to the query.

top_k = sorted(scores, desc)[:5]
🔍 Retrieval
05

Context Assembly

Top-ranked chunks are deduplicated, truncated to fit the context window, and formatted with the user's question.

prompt = f"Context:\n{chunks}\nQ: {query}"
📋 Context
06

Grounded Generation

The LLM generates an answer grounded in retrieved context, reducing hallucinations and ensuring accuracy.

Chunking Strategies

How you split documents matters. Fixed-size chunks are simple but may break semantic units. Recursive character splitting respects natural boundaries.

// Recursive Character Splitter const chunks = splitDocuments(docs, { chunkSize: 512, chunkOverlap: 50, separators: ["\n\n", "\n", ". ", " "] });
✂️

Vector Databases

Specialized databases for approximate nearest neighbor (ANN) search using HNSW, IVF, or PQ algorithms — sub-millisecond similarity search.

const results = await vectorStore.similaritySearch( queryEmbedding, 5, { scoreThreshold: 0.7 } );
🗄️

Advanced RAG Techniques

Techniques like HyDE, query rewriting, re-ranking, and self-RAG significantly improve retrieval quality.

const reranked = await reranker.score({ query: originalQuery, documents: retrievedChunks, model: "cross-encoder", topN: 3 });
